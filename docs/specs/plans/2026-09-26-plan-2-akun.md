# Plan 2 — Akun, Login, dan Dashboard

> **Untuk agent yang mengerjakan:** WAJIB memakai skill `superpowers:subagent-driven-development` (disarankan) atau `superpowers:executing-plans` untuk mengerjakan plan ini task per task. Format `- [ ]` dipakai untuk melacak progres.

**Goal:** Autentikasi berbasis `nuptk` (bukan email), proteksi sesi untuk akun nonaktif, navigasi sidebar, dashboard per peran, dan manajemen user milik admin — supaya Plan 3-5 bisa langsung mengerjakan UI tanpa membangun auth sendiri.

**Architecture:** Login dan manajemen user adalah komponen Livewire full-page yang menulis lewat service, bukan controller. Identifier login adalah kolom `users.nuptk`, jadi `config/auth.php` diubah dari `email` ke `nuptk`. Fortify sudah dibuang di Plan 1 Task 1, jadi throttle, aksi logout, dan proteksi akun nonaktif dibangun manual. Semua penulisan ke `users` lewat `UserService` supaya bisa diuji tanpa browser.

**Spec:** `docs/specs/2026-09-26-sistem-absensi-sekolah-design.md`

## Global Constraints

Nilai-nilai ini berasal dari spec §2, §3, §4, §7 dan Plan 1, lalu berlaku untuk **setiap task**. Jangan menyimpang tanpa keputusan manusia.

- **Gate versi sudah diputuskan di Plan 1 Task 1: PHP 8.3, Laravel `^13.0`.** Tidak ada fallback (D16). Plan ini memakai apa adanya hasil gate itu, tidak menentukan ulang.
- **Namespace enum adalah `App\Enums`.** `UserRole`, `AcademicPeriod`, `DayOfWeek`, `AttendanceStatus`, `StudentGender` semuanya di `app/Enums/`, bukan `app/Support/`. Hanya `NavLink` milik plan ini yang ada di `app/Support/`.
- **Factory punya state `admin()` dan `guru()`.** Gunakan `User::factory()->admin()->create()`, bukan `create(['role' => ...])`. `DemoSchoolSeeder` dan `UserFactory` sudah menyediakannya (Plan 1 Task 3).
- **NUPTK di sistem ini 18 digit angka.** `UserFactory` (`'10' . numerify('################')`) dan `DemoSchoolSeeder` (`'20' . str_pad($i, 16, ...)`) sama-sama menghasilkan 18 digit. Validasi form memakai `digits:18` supaya konsisten. Kalau sekolah ternyata memakai format lain, ubah di `UserManagement::rules()` dan `Login::rules()` — hanya dua tempat.
- **Fortify tidak ada (D17).** Semua yang biasanya diberikan Fortify — `login`, `logout`, throttle, view auth — dibangun di plan ini. Jangan `composer require laravel/fortify` untuk menyelesaikan bagian yang belum jadi.
- **Login memakai `nuptk`, bukan email (D6).** `config/auth.php` bagian `username` harus `'nuptk'`. `email` nullable dan tidak pernah jadi identitas.
- **Registrasi dimatikan (D7).** Tidak ada route, controller, view, atau test untuk pendaftaran. Form bawaan starter kit sudah dihapus di Plan 1 Task 1 Step 4.
- **Reset password lewat admin, bukan email (D8).** Tidak ada route `password.request`, `password.email`, `password.reset`, dan tabel `password_reset_tokens` sudah dibuang Plan 1 Task 1 Step 5.
- **Akun nonaktif ditolak dengan pesan jelas, bukan 403 tanpa alasan (spec §4).** Dua lapis: `AttemptAuthentication` menolak saat login, `EnsureUserIsActive` menutup kasus akun dinonaktifkan **saat session masih hidup**.
- **Wali kelas bukan role.** `role` hanya berisi `admin` atau `guru`. Status wali kelas dibaca lewat `User::homeroomClasses()`. Plan ini tidak mengaitkan wali kelas ke user — itu urusan Plan 3 saat kelas dibuat.
- **Scoping hanya di Policy dan Query Object.** Menulis kondisi role di dalam Blade adalah bug, bukan fitur. `@if (auth()->user()->isAdmin())` di sidebar **diizinkan** karena hanya menentukan link mana yang *ditampilkan* — bukan melindungi data. Semua akses data tetap lewat `authorize()` atau query.
- **Primary key UUID.** `users.id` adalah `uuid` (trait `HasUuids`). Route dan service selalu mengambil objek user dari `findOrFail`, tidak dari input mentah.
- **Test memakai SQLite in-memory** lewat `phpunit.xml` Plan 1 Task 1. `.env` tidak pernah disentuh test.
- **Semua pesan, label, validasi, dan flash message dalam bahasa Indonesia.** Nama method dan property tetap bahasa Inggris agar konsisten dengan Plan 1.
- **Layout aplikasi: `#[Layout('layouts.app')]`** untuk komponen Livewire full-page. `resources/views/layouts/app.blade.php` adalah **view**, bukan Blade component — jangan menulis `<x-layouts.app>`, komponen itu akan mencari `components/layouts/app.blade.php` yang tidak ada dan gagal dengan "Unable to locate a class or view for component". Sidebar asli ada di `resources/views/layouts/app/sidebar.blade.php` dan dirender lewat `<x-layouts::app.sidebar>` (dua titik dua, bukan titik). Tests yang perlu merender sidebar tanpa halaman nyata memakai `Blade::render('<x-layouts::app.sidebar>...</x-layouts::app.sidebar>')`.
- **Layout auth: `#[Layout('layouts.auth.card')]`** untuk komponen login. Layout auth tidak punya sidebar, dan komponen `auth-header` + `auth-session-status` dirancang untuknya. `layouts/auth.blade.php` milik starter kit sudah dihapus di Task 7 karena menunjuk `layouts::auth.simple` yang tidak pernah ada.
- **`APP_TIMEZONE=Asia/Jakarta` wajib di `.env`.** Plan 1 sudah menyetelnya. `now()->dayOfWeekIso` dipakai untuk "jadwal hari ini", jadi batas hari harus lokal.
- **`QUEUE_CONNECTION=sync`.** Tidak ada `queue:work` di shared hosting.

`app/Actions/AttemptAuthentication.php`:

```php
<?php

namespace App\Actions;

use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Str;
use Illuminate\Validation\ValidationException;

class AttemptAuthentication
{
    private const MAX_ATTEMPTS = 5;

    private const DECAY_SECONDS = 60;

    /**
     * Coba login dengan kredensial dari form.
     *
     * Sengaja bukan Illuminate\Foundation\Auth\AuthenticatesUsers, karena
     * kelas itu mengasumsikan identitas login adalah email dan tidak punya
     * tempat untuk pesan "akun dinonaktifkan".
     *
     * @param  array<string, mixed>  $credentials
     *
     * @throws ValidationException
     */
    public function attempt(array $credentials): void
    {
        $key = self::throttleKeyFor((string) $credentials['nuptk'], request()->ip());

        if (RateLimiter::tooManyAttempts($key, self::MAX_ATTEMPTS)) {
            $seconds = RateLimiter::availableIn($key);

            throw ValidationException::withMessages([
                'nuptk' => [__('auth.throttle', ['seconds' => $seconds])],
            ]);
        }

        $authenticated = Auth::attempt([
            'nuptk' => $credentials['nuptk'],
            'password' => $credentials['password'],
        ], (bool) ($credentials['remember'] ?? false));

        if (! $authenticated) {
            RateLimiter::hit($key, self::DECAY_SECONDS);

            $this->fail(__('auth.failed'));
        }

        $user = Auth::user();

        if (! $user instanceof User) {
            Auth::logout();

            $this->fail(__('auth.failed'));
        }

        if (! $user->is_active) {
            Auth::logout();

            $this->fail('Akun ini sudah dinonaktifkan. Hubungi admin.');
        }

        RateLimiter::clear($key);
    }

    /**
     * Bangun kunci throttle dari nuptk dan IP.
     *
     * Dipakai dua kali: oleh attempt() di bawah, dan oleh named limiter
     * 'login' di AppServiceProvider. Satu implementasi supaya kedua jalur
     * tidak pernah menghitung kunci yang berbeda.
     */
    public static function throttleKeyFor(string $nuptk, ?string $ip): string
    {
        return 'login|'.Str::lower($nuptk).'|'.(string) $ip;
    }

    private function fail(string $message): never
    {
        throw ValidationException::withMessages([
            'nuptk' => [$message],
        ]);
    }
}
```

Tiga hal di file ini yang mudah salah:

1. **Query user tidak dilakukan manual.** `Auth::attempt()` sudah cukup, dan ia mengembalikan user yang berhasil diotorisasi. Menjalankan `User::where('nuptk')->first()` lebih dulu berarti dua query per percobaan login, termasuk saat percobaan itu akan ditolak throttle.
2. **Pengecekan `is_active` dilakukan setelah `Auth::attempt`, bukan sebelumnya.** Kalau dicepat, `Hash::check` tetap jalan dua kali dan setiap login yang gagal memerlukan dua query. Selain itu, pesan "akun dinonaktifkan" akan bocor tanpa password yang benar.
3. **`RateLimiter::hit()` hanya dipanggil saat gagal.** Kalau dipanggil juga saat berhasil, satu orang yang login benar tapi lambat akan mengunci dirinya sendiri di percobaan berikutnya.
4. **Tidak ada kolom `last_login_at`.** Kebutuhan itu tidak ada di v1 (spec §10), jadi tidak ada alasan menambah kolom yang tidak pernah dibaca. Kalau nanti dibutuhkan, itu fitur tersendiri dengan migration dan testnya sendiri.

`AttemptAuthentication` **tidak** menyentuh `users` sama sekali selain `Auth::attempt()` membaca user. Tidak ada penulisan ke database di kelas ini, jadi tidak ada transaksi dan tidak ada race condition di lapisan ini.

`app/Http/Middleware/EnsureUserIsActive.php`:

```php
<?php

namespace App\Http\Middleware;

use App\Models\User;
use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Symfony\Component\HttpFoundation\Response;

class EnsureUserIsActive
{
    public function handle(Request $request, Closure $next): Response
    {
        $user = $request->user();

        if ($user instanceof User && ! $user->is_active) {
            Auth::logout();

            $request->session()->invalidate();
            $request->session()->regenerateToken();

            return redirect()
                ->route('login')
                ->withErrors([
                    'nuptk' => 'Akun ini sudah dinonaktifkan. Hubungi admin.',
                ]);
        }

        return $next($request);
    }
}
```

Middleware ini menutup kasus yang **tidak** bisa ditutup `AttemptAuthentication`: akun aktif waktu login, lalu dinonaktifkan admin beberapa jam kemudian sementara session masih hidup. Tanpa middleware ini, akun yang sudah dinonaktifkan tetap bisa absensi sampai session-nya kedaluwarsa.

Sengaja dipasang sebagai **middleware kelas penuh**, bukan alias. Alias harus didaftarkan di `bootstrap/app.php` dengan nama; kelas penuh langsung bisa dipakai di grup route tanpa pendaftaran, sehingga Plan 4 dan Plan 5 cukup menulis `->middleware(EnsureUserIsActive::class)` tanpa menyentuh `bootstrap/app.php` lagi.

```php
use App\Actions\AttemptAuthentication;
use App\Models\User;
use App\Policies\UserPolicy;
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Gate;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\ServiceProvider;

    public function register(): void
    {
        //
    }

    public function boot(): void
    {
        Model::shouldBeStrict(! $this->app->isProduction());

        Gate::policy(User::class, UserPolicy::class);

        RateLimiter::for('login', function (Request $request) {
            return Limit::perMinute(5)->by(

                    (string) $request->ip()

        });
```

`Model::shouldBeStrict()` **dipertahankan** dari `AppServiceProvider` bawaan starter kit. Mengganti seluruh isi file tanpa ikut membawa baris ini berarti diam-diam mematikan `preventAccessingMissingAttributes` — kesalahan seperti `$user->nuptk` salah ketik atau atribut yang tidak ada di migration tidak lagi meledak, tapi menghasilkan `null` yang diteruskan ke database. Untuk aplikasi absensi, `null` yang lolos ke kolom `NOT NULL` jauh lebih sulit ditelusuri daripada error yang berhenti di baris pertama.

Kunci throttle **dibangun di satu tempat saja**, yaitu `AttemptAuthentication::throttleKeyFor()`, lalu dipakai oleh kedua pemanggilnya. Kalau `nuptk` + IP dirangkai dua kali di dua file, satu hari pasti berubah hanya satu file — dan throttle tetap lolos hanya pada satu jalur login, dengan limiter bernama yang tidak pernah terpakai. Kunci throttle dibangun dari `nuptk` + IP, bukan `email`. Kalau `email` yang dipakai dan email kosong (`null` di database), semua akun tanpa email akan berbagi satu kunci — satu orang gagal login cukup untuk mengunci semua orang.

`Gate::policy(User::class, UserPolicy::class)` sebenarnya tidak wajib: Laravel 11+ menemukan `App\Policies\UserPolicy` untuk `App\Models\User` secara otomatis. Didaftarkan eksplisit supaya hubungan model-policy terlihat di satu tempat, dan supaya plan ini tidak bergantung pada perilaku auto-discovery.

```php
<?php

namespace App\Livewire\Auth;

use App\Actions\AttemptAuthentication;
use Livewire\Attributes\Layout;
use Livewire\Attributes\Validate;
use Livewire\Component;

#[Layout('layouts.auth.card')]
class Login extends Component
{
    #[Validate('required|string|digits:18|max:20')]
    public string $nuptk = '';

    #[Validate('required|string|min:8')]
    public string $password = '';

    #[Validate('nullable|boolean')]
    public bool $remember = false;

    public function authenticate(AttemptAuthentication $action): void
    {
        $this->validate();

        try {
            $action->attempt([
                'nuptk' => $this->nuptk,
                'password' => $this->password,
                'remember' => $this->remember,
            ]);
        } finally {
            $this->password = '';
        }

        $this->redirectIntended(route('dashboard'), navigate: false);
    }

    public function render()
    {
        return view('livewire.auth.login');
    }
}
```

`app/Services/UserService.php`:

```php
<?php

namespace App\Services;

use App\Enums\UserRole;
use App\Exceptions\LastActiveAdminException;
use App\Models\User;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

class UserService
{
    /**
     * @param  array{name: string, nuptk: string, email: ?string, password: string, role: string}  $data
     */
    public function create(array $data): User
    {
        return DB::transaction(function () use ($data): User {
            $this->guardDuplicateNuptk($data['nuptk']);

            return User::query()->create([
                'name' => trim($data['name']),
                'nuptk' => $data['nuptk'],
                'email' => $this->normaliseEmail($data['email']),
                'password' => Hash::make($data['password']),
                'role' => UserRole::from($data['role']),
                'is_active' => true,
            ]);
        });
    }

    /**
     * @param  array{name: string, nuptk: string, email: ?string, role: string}  $data
     */
    public function update(User $user, array $data): User
    {
        return DB::transaction(function () use ($user, $data): User {
            if ($data['nuptk'] !== $user->nuptk) {
                $this->guardDuplicateNuptk($data['nuptk']);
            }

            if ($this->wouldRemoveLastActiveAdmin($user, $data['role'])) {
                throw new LastActiveAdminException;
            }

            $user->name = trim($data['name']);
            $user->nuptk = $data['nuptk'];
            $user->email = $this->normaliseEmail($data['email']);
            $user->role = UserRole::from($data['role']);
            $user->save();

            return $user;
        });
    }

    public function resetPassword(User $user, string $plainPassword): void
    {
        $user->password = Hash::make($plainPassword);
        $user->save();
    }

    public function toggleActive(User $actor, User $target): void
    {
        if ($actor->is($target)) {
            throw new LastActiveAdminException;
        }

        if ($target->is_active && $this->isLastActiveAdmin($target)) {
            throw new LastActiveAdminException;
        }

        $target->is_active = ! $target->is_active;
        $target->save();
    }

    /**
     * Soft delete. Absensi yang sudah tercatat tetap utuh karena attendances
     * tidak punya FK cascade ke users.
     */
    public function delete(User $actor, User $target): void
    {
        if ($actor->is($target)) {
            throw new LastActiveAdminException;
        }

        if ($this->isLastActiveAdmin($target)) {
            throw new LastActiveAdminException;
        }

        $target->delete();
    }

    /**
     * Admin aktif terakhir yang sedang diedit akan kehilangan aksesnya kalau
     * form mengubah role-nya jadi guru.
     */
    private function wouldRemoveLastActiveAdmin(User $user, string $newRole): bool
    {
        return $user->role === UserRole::Admin
            && $user->is_active
            && $newRole !== UserRole::Admin->value
            && $this->activeAdminCount() <= 1;
    }

    private function isLastActiveAdmin(User $user): bool
    {
        return $user->role === UserRole::Admin
            && $user->is_active
            && $this->activeAdminCount() <= 1;
    }

    private function activeAdminCount(): int
    {
        return User::query()
            ->where('role', UserRole::Admin->value)
            ->where('is_active', true)
            ->count();
    }

    private function guardDuplicateNuptk(string $nuptk): void
    {
        if (User::withTrashed()->where('nuptk', $nuptk)->exists()) {
            throw ValidationException::withMessages([
                'form.nuptk' => ['NUPTK ini sudah dipakai user lain.'],
            ]);
        }
    }

    private function normaliseEmail(?string $email): ?string
    {
        $email = trim((string) $email);

        return $email === '' ? null : $email;
    }
}
```

Empat aturan di `UserService` adalah tempat tunggal yang mencegah sistem mengunci dirinya sendiri:

1. Admin tidak boleh menonaktifkan atau menghapus dirinya sendiri — dia tidak akan bisa login lagi untuk membatalkannya.
2. Admin aktif terakhir tidak boleh dinonaktifkan atau dihapus — tanpa itu, satu klik salah membuat sistem tidak bisa dikelola siapa pun.
3. Admin aktif terakhir tidak boleh turun role-nya jadi guru lewat form edit — jalur yang sering terlewat karena `update()` bukan `toggleActive()`.
4. `guardDuplicateNuptk` memakai `withTrashed()`, karena user yang soft-delete masih memegang NUPTK-nya.

Semua operasi tulis dibungkus `DB::transaction()`. `create` dan `update` bisa membaca lalu menulis; tanpa transaksi, dua admin yang disimpan bersamaan bisa sama-sama lolos pemeriksaan "admin terakhir" dan menghasilkan dua admin aktif.

```php
namespace App\Livewire;

use App\Enums\UserRole;
use App\Exceptions\LastActiveAdminException;
use App\Models\User;
use App\Services\UserService;
use Illuminate\Validation\Rule;
use Livewire\Attributes\Layout;
use Livewire\Component;
use Livewire\WithPagination;

#[Layout('layouts.app')]
class UserManagement extends Component
{
    use WithPagination;

    public string $search = '';

    /** @var array{id: ?string, name: string, nuptk: string, email: string, role: string} */
    public array $form = [
        'id' => null,
        'name' => '',
        'nuptk' => '',
        'email' => '',
        'role' => 'guru',
    ];

    public bool $showForm = false;

    public string $password = '';

    public string $password_confirmation = '';

    public ?string $resetTargetId = null;

    public string $resetTargetName = '';

    public function updatedSearch(): void
    {
        $this->resetPage();
    }

    public function create(): void
    {
        $this->authorize('create', User::class);

        $this->form = [
            'id' => null,
            'name' => '',
            'nuptk' => '',
            'email' => '',
            'role' => UserRole::Guru->value,
        ];

        $this->password = '';
        $this->password_confirmation = '';
        $this->showForm = true;
        $this->clearValidation();
    }

    public function edit(string $id): void
    {
        $user = User::findOrFail($id);

        $this->authorize('update', $user);

        $this->form = [
            'id' => $user->id,
            'name' => $user->name,
            'nuptk' => $user->nuptk,
            'email' => $user->email ?? '',
            'role' => $user->role->value,
        ];

        $this->password = '';
        $this->password_confirmation = '';
        $this->showForm = true;
        $this->clearValidation();
    }

    public function cancelForm(): void
    {
        $this->showForm = false;
        $this->clearValidation();
    }

    public function save(UserService $service): void
    {
        $isUpdate = $this->form['id'] !== null;

        $this->authorize($isUpdate ? 'update' : 'create', $isUpdate
            ? User::findOrFail($this->form['id'])
            : User::class);

        $rules = [
            'form.name' => ['required', 'string', 'max:255'],
            'form.nuptk' => [
                'required',
                'string',
                'digits:18',
                'max:20',
                Rule::unique('users', 'nuptk')->ignore($this->form['id']),
            ],
            'form.email' => ['nullable', 'email', 'max:255'],
            'form.role' => ['required', Rule::in([
                UserRole::Admin->value,
                UserRole::Guru->value,
            ])],
        ];

        if (! $isUpdate) {
            $rules['password'] = ['required', 'string', 'min:8', 'confirmed'];
        }

        $this->validate($rules);

        try {
            if ($isUpdate) {
                $service->update(
                    User::findOrFail($this->form['id']),
                    $this->form
                );

                $this->dispatch('user-updated');
            } else {
                $service->create([
                    'name' => $this->form['name'],
                    'nuptk' => $this->form['nuptk'],
                    'email' => $this->form['email'],
                    'role' => $this->form['role'],
                    'password' => $this->password,
                ]);

                $this->dispatch('user-created');
            }
        } catch (LastActiveAdminException $exception) {
            $this->addError('form.role', $exception->getMessage());

            return;
        }

        $this->showForm = false;
        $this->password = '';
        $this->password_confirmation = '';
        $this->clearValidation();
    }

    public function toggleActive(string $id, UserService $service): void
    {
        $target = User::findOrFail($id);

        $this->authorize('update', $target);

        try {
            $service->toggleActive(auth()->user(), $target);
        } catch (LastActiveAdminException $exception) {
            $this->dispatch('toast', type: 'danger', message: $exception->getMessage());
        }
    }

    public function delete(string $id, UserService $service): void
    {
        $target = User::findOrFail($id);

        $this->authorize('delete', $target);

        try {
            $service->delete(auth()->user(), $target);
        } catch (LastActiveAdminException $exception) {
            $this->dispatch('toast', type: 'danger', message: $exception->getMessage());
        }
    }

    public function startReset(string $id): void
    {
        $user = User::findOrFail($id);

        $this->authorize('update', $user);

        $this->resetTargetId = $user->id;
        $this->resetTargetName = $user->name;
        $this->password = '';
        $this->password_confirmation = '';
        $this->clearValidation();
    }

    public function cancelReset(): void
    {
        $this->resetTargetId = null;
        $this->resetTargetName = '';
        $this->password = '';
        $this->password_confirmation = '';
        $this->clearValidation();
    }

    public function confirmReset(UserService $service): void
    {
        $this->authorize('update', User::findOrFail($this->resetTargetId));

        $this->validate([
            'password' => ['required', 'string', 'min:8', 'confirmed'],
        ]);

        $service->resetPassword(
            User::findOrFail($this->resetTargetId),
            $this->password
        );

        $this->dispatch('password-reset', name: $this->resetTargetName);

        $this->cancelReset();
    }

    public function render()
    {
        return view('livewire.user-management', [
            'users' => User::query()
                ->when($this->search !== '', function ($query): void {
                    $query->where(function ($inner): void {
                        $inner->where('name', 'like', '%'.$this->search.'%')
                            ->orWhere('nuptk', 'like', '%'.$this->search.'%');
                    });
                })
                ->orderBy('name')
                ->paginate(15),
            'roles' => UserRole::cases(),
        ]);
    }
}
```

Tiga hal di component ini yang tidak boleh dilewati:

1. **`$this->authorize(...)` ada di setiap aksi mutasi, bukan hanya di `render()`.** Livewire memvalidasi component yang di-mount, bukan method yang dipanggil. Guru yang berhasil menyamar dengan URL `/user` masih bisa memanggil `delete()` langsung — `authorize` di action satu-satunya pagar.
2. **`Rule::unique('users', 'nuptk')->ignore($this->form['id'])`** mencegah user tidak bisa menyimpan form-nya sendiri tanpa perubahan apa pun, karena `nuptk`-nya sudah ada di database.
3. **Validasi `password` ada di luar `rules()` array `$form`.** Atributnya bukan `form.password` melainkan property `$password`, dengan pasangan `password_confirmation` yang dipakai aturan `confirmed`. Kalau kedua property itu tidak bernama `password` + `password_confirmation`, validasi `confirmed` diam-diam lolos untuk semua input.
4. **`save()` mengoper instance yang akan diubah, bukan nama class-nya.** `$this->authorize('update', User::class)` membuat policy menerima class string, sehingga `UserPolicy::update(User $target)` tidak pernah dipanggil dan cek "hanya admin" hilang. Bentuk yang benar: `authorize($isUpdate ? 'update' : 'create', $isUpdate ? User::findOrFail($this->form['id']) : User::class)`. Karena itu `test_guru_tidak_bisa_menjalankan_aksi_mutasi` benar-benar ditolak, bukan lolos karena policy tidak pernah jalan.

```php
<?php

namespace App\Support;

class NavLink
{
    public function __construct(
        public readonly string $label,
        public readonly string $routeName,
        public readonly string $icon,
        public readonly bool $adminOnly = false,
    ) {
    }

    public static function adminOnly(
        string $label,
        string $routeName,
        string $icon,
    ): self {
        return new self($label, $routeName, $icon, true);
    }

    public function visibleTo(bool $isAdmin): bool
    {
        return ! $this->adminOnly || $isAdmin;
    }

    /**
     * @return array{label: string, routeName: string, icon: string, adminOnly: bool}
     */
    public function toArray(): array
    {
        return [
            'label' => $this->label,
            'routeName' => $this->routeName,
            'icon' => $this->icon,
            'adminOnly' => $this->adminOnly,
        ];
    }
}
```

```php
<?php

namespace App\Livewire;

use App\Enums\AttendanceStatus;
use App\Models\AcademicYear;
use App\Models\Attendance;
use App\Models\Schedule;
use App\Models\SchoolClass;
use Livewire\Attributes\Layout;
use Livewire\Component;

#[Layout('layouts.app')]
class Dashboard extends Component
{
    public function render()
    {
        $user = auth()->user();

        $academicYear = AcademicYear::query()
            ->where('is_active', true)
            ->first();

        $schedules = Schedule::query()
            ->where('teacher_id', $user->id)
            ->where('day_of_week', now()->dayOfWeekIso)
            ->with(['subject', 'schoolClass'])
            ->orderBy('start_time')
            ->get();

        return view('livewire.dashboard', [
            'academicYear' => $academicYear,
            'schedules' => $schedules,
            'counts' => $this->todayCounts($schedules->pluck('id')),
            'homeroomCount' => $user->isAdmin()
                ? SchoolClass::query()->count()
                : $user->homeroomClasses()->count(),
        ]);
    }

    /**
     * @param  \Illuminate\Support\Collection<int, string>  $scheduleIds
     * @return array{hadir: int, izin: int, sakit: int, alpa: int}
     */
    private function todayCounts($scheduleIds): array
    {
        $statuses = [
            AttendanceStatus::Hadir->value => 'hadir',
            AttendanceStatus::Izin->value => 'izin',
            AttendanceStatus::Sakit->value => 'sakit',
            AttendanceStatus::Alpa->value => 'alpa',
        ];

        $counts = ['hadir' => 0, 'izin' => 0, 'sakit' => 0, 'alpa' => 0];

        if ($scheduleIds->isEmpty()) {
            return $counts;
        }

        $rows = Attendance::query()
            ->whereIn('schedule_id', $scheduleIds)
            ->whereDate('date', today())
            ->selectRaw('status, count(*) as total')
            ->groupBy('status')
            ->pluck('total', 'status');

        foreach ($rows as $status => $total) {
            if (isset($statuses[$status])) {
                $counts[$statuses[$status]] = (int) $total;
            }
        }

        return $counts;
    }

    public function getSalamProperty(): string
    {
        $jam = now()->hour;

        return match (true) {
            $jam < 11 => 'Selamat pagi',
            $jam < 15 => 'Selamat siang',
            $jam < 19 => 'Selamat sore',
            default => 'Selamat malam',
        };
    }
}
```

Empat hal di component ini:

1. **`AcademicYear` tidak memakai `firstOrFail()`.** Kalau admin belum mengatur tahun ajaran aktif, `firstOrFail()` melempar 404 dan guru melihat halaman error. Plan ini mengembalikan `null` dan view menampilkan pesan yang bisa ditindaklanjuti.
2. **`whereDate('date', today())` wajib, tidak cukup `whereIn('schedule_id', ...)`.** Jadwal hari Senin yang sama dipakai ulang tiap minggu, jadi tanpa filter tanggal ringkasan akan menjumlahkan seluruh sejarah.
3. **`$scheduleIds->isEmpty()` dicek sebelum query.** `whereIn` dengan array kosong sudah aman di Laravel, tapi pengecekan eksplisit membuat tidak ada satu pun query absensi yang dikirim ke database pada hari tanpa jadwal.
4. **`getSalamProperty()` dihitung, bukan ditulis di view.** View hanya menampilkan `{{ $salam }}`. Perhitungan sapaan di dalam view tidak bisa diuji, dan setiap view yang butuh sapaan akan mengulang `match` yang sama.

`pluck('total', 'status')` mengembalikan key enum sebagai array key PHP, dan PHP akan melempar error "Illegal offset type" kalau key-nya objek. Karena itu `selectRaw('status, ...')` dipilih — dia mengembalikan string biasa dari database, bukan enum yang sudah di-cast.

## Koreksi terhadap Plan (hasil eksekusi)

Plan ini sudah dikerjakan task per task di branch `feat/plan-2-akun`. Halaman-halaman di atas ditulis sebelum ada kode, jadi beberapa asumsi meleset. Semua koreksi di bawah sudah terpasang di production code dan **wajib dipakai plan 3-5** — jangan menyalin ulang versi yang salah dari langkah-langkah di atas.

### Aturan yang berlaku untuk semua plan berikutnya

| Asumsi plan | Kenyataan |
|---|---|
| `php artisan test` 79 test baseline | 83 test |
| Layout aplikasi `<x-layouts.app title="...">` | `#[Layout('layouts.app')]`. `layouts/app.blade.php` itu **view**, bukan Blade component |
| `flux:table.head` / `.headcell` / `.body` | Tidak ada di Flux terpasang. Pakai `flux:table.columns` + `flux:table.column` dan `flux:table.rows` + `flux:table.row` + `flux:table.cell` |
| `{{ $paginator->links() }}` | `flux:table :paginate="$paginator"` (Flux yang menrender `flux:pagination`) |
| `flux:empty-state` | Tidak ada. Tulis div biasa dengan dua baris teks |
| `getXxxProperty()` tersedia sebagai `$xxx` di view | Livewire 4 tidak mengekstrak computed property ke view data. Butuh `#[Computed]` **dan** diakses sebagai `{{ $this->xxx }}` |
| `Limit::by()->max()->decay()` | `new Limit(key: ..., maxAttempts: ..., decaySeconds: ...)` |
| `$request->setRemoteAddr()` | `$request->server->set('REMOTE_ADDR', ...)` |

### Per task

**Task 1–3** (`7e8be56`, `0a010dc`, `3261cf8`)

- Semua test yang menulis database butuh `use RefreshDatabase`. Plan tidak menyebutkannya di mana pun, dan `phpunit.xml` tidak memakainya secara global.
- Assertion jumlah detik throttle harus pakai regex (`#\d+#`), bukan angka tetap — waktu eksekusi membuat hasilnya bergeser.

**Task 4** (`a81f167`)

- **`mount()` wajib `authorize('viewAny', User::class)`.** Plan hanya mengotorisasi action, tapi `test_hanya_admin_yang_bisa_membuka_halaman` menuntut guru dapat 403 dari `GET /user`. Tanpa guard di `mount()`, halaman membocorkan daftar akun ke guru, dan `Livewire::test()` tidak bisa dipakai untuk menguji action karena mount-nya menolak.
- Karena itu dua test guru diuji di lapis `Gate::forUser($guru)->allows(...)`, bukan `Livewire::test()->assertForbidden()`. Ditambah satu test positif untuk admin.
- `confirmReset()` wajib menolak `resetTargetId === null` sebelum `findOrFail()`, kalau tidak error 404 tidak menjelaskan apa pun.
- View: tanpa `<x-layouts.app>`, tanpa `flux:empty-state`, table pakai API Flux yang benar.
- `Gate::policy(User::class, UserPolicy::class)` didaftarkan di `AppServiceProvider::registerPolicies()`.
- Link `profile.edit` dihapus dari `layouts/app/sidebar.blade.php` **dan** `components/desktop-user-menu.blade.php` — keduanya memanggil `route('profile.edit')` yang dihapus Task 1, dan sidebar dirender di setiap halaman.
- `UserManagementTest` memasang route double `dashboard` di `setUp()` (sidebar memanggilnya; route asli baru ada di Task 6).

**Task 5** (`5e30c8f`)

- `SidebarTest` harness pakai `Blade::render('<x-layouts::app.sidebar>...</x-layouts::app.sidebar>')`, bukan `<x-layouts.app>`. Mehr test lewat `/dashboard` akan mengikat Task 5 ke Task 6.
- `public/fonts-manifest.dev.json` masuk `.gitignore`. File itu dibuat otomatis saat test merender layout penuh dan isinya URL dev server Vite lokal (`http://[::1]:5173/...`).

**Task 6** (`3d39132`)

- **`DashboardTest` wajib membekukan waktu** ke Senin (`Carbon::setTestNow()`, di-reset di `tearDown()`). `DayOfWeek` hanya punya 1-5, sedangkan `now()->dayOfWeekIso` mengembalikan 6/7 pada akhir pekan — `DayOfWeek::from(7)` melempar `ValueError`. Tanpa ini suite hanya hijau hari Senin–Jumat.
- `test_ringkasan_absensi_hari_ini_dihitung_per_status` harus membuat **4** siswa, bukan 3: plan mengiterasi 4 status absensi dengan indeks 0-3.
- Assertion kelas adalah `assertSee($kelas->name)`, bukan `assertSee('Kelas '.$kelas->name)` — `SchoolClass.name` sudah berupa `"VII-A"` dan header kolomnya sudah "Kelas".

- `resources/views/layouts/auth.blade.php` dihapus. File itu memanggil `x-layouts::auth.simple` yang tidak pernah ada, tidak direferensikan class/test/view mana pun, dan **`view:cache` gagal** karena itu — langkah wajib sebelum deploy ke shared hosting.
